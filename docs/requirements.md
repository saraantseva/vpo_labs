# Спецификация требований

**Проект:** Blogers & Stories
**Версия:** 1.0
**Дата:** 2026-10-05

## 1. Введение

### 1.1 Назначение документа
Настоящий документ описывает бизнес-, пользовательские, функциональные и
нефункциональные требования к приложению **Blogers & Stories**. Документ
используется как основа для проектирования, разработки, тестирования и
приёмки продукта.

### 1.2 Область применения
Приложение предназначено для ведения персональной базы блогеров и
связанных с ними публикаций (историй). Работает локально, без серверной части.

### 1.3 Соглашения
- **BR** — бизнес-требование (Business Requirement)
- **UC** — пользовательский сценарий (Use Case)
- **FR** — функциональное требование (Functional Requirement)
- **NFR** — нефункциональное требование (Non-Functional Requirement)

## 2. Бизнес-требования

### 2.1 Назначение системы
Система «Blogers & Stories» — офлайн-приложение для ведения структурированной
базы инфлюенсеров (блогеров) и их публикаций. Заменяет разрозненные заметки,
таблицы и текстовые файлы единым приложением с валидацией данных, поиском и
визуальной аналитикой.

### 2.2 Решаемая проблема
- **Разрозненность данных** — информация о блогерах и их публикациях хранится
  в заметках, таблицах и мессенджерах, что затрудняет её поиск и обновление.
- **Отсутствие валидации** — при ручном ведении легко допустить ошибки
  (отрицательное число подписчиков, пустой никнейм, дубликаты).
- **Нет визуальной аналитики** — невозможно быстро оценить популярность
  публикации без ручного подсчёта.
- **Привязка зависимостей** — отсутствие связи «блогер ↔ истории» усложняет
  навигацию по контенту.

### 2.3 Цели
| ID | Цель |
|---|---|
| G-1 | Предоставить единое место для хранения информации о блогерах и их историях |
| G-2 | Обеспечить целостность данных через валидацию на уровне домена |
| G-3 | Дать пользователю быстрый доступ к публикациям конкретного блогера |
| G-4 | Обеспечить наглядную визуализацию популярности публикаций |
| G-5 | Поддержать офлайн-работу на Windows и Android |

### 2.4 Бизнес-требования
| ID | Формулировка | Обоснование |
|---|---|---|
| BR-1 | Система должна обеспечивать ведение базы блогеров (CRUD) | Основной сценарий использования |
| BR-2 | Система должна обеспечивать ведение историй, связанных с блогерами | Ядро предметной области |
| BR-3 | Система должна работать автономно, без подключения к сети | Целевые пользователи часто работают офлайн |
| BR-4 | Система должна поддерживать Windows и Android | Кроссплатформенность заявлена как цель проекта |
| BR-5 | Система должна сохранять введённые данные между сессиями в рамках жизненного цикла БД | Обеспечение непрерывности работы пользователя |
| BR-6 | Система должна предотвращать ввод некорректных данных на уровне домена | Целостность данных |

## 5. Нефункциональные требования

| ID | Категория | Формулировка | Способ проверки |
